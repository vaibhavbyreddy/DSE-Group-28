\chapter{Verification and Validation Plan}
\label{ch: VandV}
The methods used to size the design need to be verified and validated. This means ensuring the method is implemented according to its specification (verification) and assessing the relevance of the method and its ability to accurately reproduce physics (validation). 

The verification is highly dependent on how the method is implemented. For project HUGO, the design options are sized using iterative code \footref{url:github_repo}. The code executes several independent analyses in a loop. After each analysis, parts of a global single source of truth object representing the aircraft are updated. The loop runs for a pre-determined amount of steps and values of selected parameters are saved at each iteration.

This setup allows to verify the particular analyses themselves. Per-analysis verification is described in the relevant sections of \autoref{ch:engineering_design}. As a guideline, particular analyses are expected to be general enough to model both HUGO and the verification case.

It is also necessary to ensure the iterative sizing converges. This is done by tracking the history of aircraft MTOM for each iteration step for each configuration. The results of the convergence study are shown in \autoref{fig:midtermIteration}. Based on that, eight iterations were chosen for the Midterm Report trade-off, as from that point the difference in mass between the design options stays constant and the simulation runtime is acceptable for conducting a sensitivity study on the four configurations (approximately 20 minutes per parameter).  For the sizing of the final design, a similar convergence study shall be conducted. Nevertheless, due to higher precision required for the final design, a larger number of iterations may be required.

As for the validation, the main goal for the analyses of the Midterm Report is to provide numerical data for the trade-off. As such, a sensitivity study is conducted in \autoref{sec: sensitivity study} to assess whether the analyses' predictions will not change to an extent that affects the trade-off with varying their assumptions.

For the Final Report, the goal of the analyses is to provide accurate numerical values used for subsystem design. As such, it can be verified by employing the same analysis to evaluate an existing aircraft, and compare its results with real aircraft data. This will require detailed information on the reference aircraft of choice. The analysis will also have to be general enough to accommodate both HUGO and the reference aircraft. The need for validation may thus be driving for the development of the Final Report methods. Depending on the availability of statistical data, it might be necessary to validate different parts of the method against different reference aircraft.

A sensitivity study shall be conducted for the analyses from the Final Report as well. In that case, the question to answer will be if changes to assumptions significantly affect subsystem design or final system performance.
